# LinkAI: специфікація продукту

## 1. Мета

LinkAI — VS Code-плагін із власним екраном для відстеження прогресу розробника. Плагін показує статистику написаних рядків, динаміку активності та оцінку покращення навичок у вибраній мові програмування.

Оцінка виконується після натискання кнопки **«Перевірити»**. Фронтенд відповідає за інтерфейс, локальний збір агрегованої статистики та відображення результату. Аналіз і генерація рекомендацій виконуються зовнішнім AI-бекендом.

## 2. Межі першої версії

### Входить до MVP

- окремий екран LinkAI у VS Code;
- вибір мови програмування;
- вибір періоду статистики;
- підрахунок написаних рядків і змінених рядків;
- графік активності за днями;
- порівняння поточного періоду з попереднім;
- кнопка **«Перевірити»**;
- отримання оцінки прогресу та рекомендацій від AI-бекенду;
- стани завантаження, успіху та помилки;
- базові налаштування приватності та адреси API.

### Не входить до MVP

- власний сервер або база даних;
- авторизація користувачів;
- командна статистика;
- рейтинг розробників;
- редагування або збереження сирого коду на стороні плагіна;
- автоматичний AI-аналіз без явної дії користувача.

## 3. Користувацький сценарій

1. Користувач відкриває команду `LinkAI: Відкрити статистику`.
2. На екрані обирає мову програмування та період.
3. Переглядає локально зібрану статистику.
4. Натискає **«Перевірити»**.
5. Фронтенд формує агрегований запит без сирого коду та надсилає його AI-бекенду.
6. Після відповіді відображаються оцінка, зміна відносно попереднього періоду та рекомендації.
7. Користувач може змінити мову або період і повторити перевірку.

## 4. Екран статистики

Екран реалізується як `WebviewView` або `WebviewPanel` у стилі VS Code та має бути доступним із Activity Bar і Command Palette.

### Верхня панель

- назва `LinkAI`;
- вибір мови: `TypeScript`, `JavaScript`, `Python`, `Java`, `C#`, `Go`, `C++` та `Інша`;
- вибір періоду: `7 днів`, `30 днів`, `90 днів`;
- кнопка **«Перевірити»**;
- індикатор часу останньої перевірки.

### Блоки екрана

#### Ключові показники

- написано рядків;
- змінено рядків;
- активні дні;
- кількість сесій;
- середня кількість рядків за активний день.

#### Динаміка

Лінійний або стовпчиковий графік активності за днями. Графік має показувати кількість написаних рядків і дозволяти навести курсор на конкретну дату.

#### Порівняння

Показує зміни щодо попереднього періоду:

- відсоток зміни кількості рядків;
- зміна активних днів;
- зміна середньої щоденної активності;
- напрямок прогресу: зростання, стабільність або спад.

#### AI-оцінка

Після натискання **«Перевірити»** відображаються:

- оцінка прогресу від 0 до 100;
- коротке пояснення оцінки;
- сильні сторони;
- 2–4 конкретні рекомендації;
- застереження, якщо даних недостатньо для надійної оцінки.

Оцінка не повинна подаватися як абсолютний показник професійного рівня. В інтерфейсі слід називати її орієнтовною оцінкою прогресу за вибраний період.

## 5. Метрики

Фронтенд може обчислювати такі метрики з подій редактора та відкритих документів:

- `linesAdded` — кількість нових рядків;
- `linesDeleted` — кількість видалених рядків;
- `linesChanged` — `linesAdded + linesDeleted`;
- `activeDays` — кількість календарних днів із кодовою активністю;
- `sessions` — кількість сесій активності;
- `averageLinesPerActiveDay` — `linesAdded / activeDays`;
- `periodComparison` — різниця поточного та попереднього періодів у відсотках.

Статистика має рахуватися окремо для кожної мови. За замовчуванням ураховуються тільки файли робочої області, виключені директорії та файли з `.gitignore` не враховуються.

Рядки коментарів, порожні рядки та автоматично згенеровані файли бажано позначати окремими категоріями або виключати з основної метрики. Правило має бути однаковим для поточного та попереднього періодів.

## 6. Frontend-архітектура

### Extension host

Відповідає за:

- реєстрацію команди та webview;
- читання подій VS Code;
- визначення мови файлу;
- підрахунок локальних агрегатів;
- зберігання налаштувань через `workspaceState` або `globalState`;
- обмін повідомленнями між extension host і webview;
- виклик AI-бекенду через окремий клієнтський сервіс.

### Webview UI

Відповідає за:

- рендеринг статистики;
- фільтри мови та періоду;
- графіки;
- стани завантаження та помилки;
- відображення AI-оцінки;
- надсилання команд до extension host через `postMessage`.

UI не має містити секретних ключів, прямого доступу до файлової системи або логіки збереження сирого коду.

Рекомендована структура:

```text
src/
  extension.ts
  services/
    statistics.ts
    aiClient.ts
  webview/
    app.ts
    styles.css
  types/
    messages.ts
    statistics.ts
```

## 7. Обмін повідомленнями

Повідомлення між extension host і webview мають бути типізованими.

### Події з webview

```ts
{ type: "setLanguage", language: string }
{ type: "setPeriod", period: 7 | 30 | 90 }
{ type: "requestStatistics" }
{ type: "requestCheck" }
```

### Події до webview

```ts
{
  type: "statisticsReady",
  payload: {
    language: string,
    period: 7 | 30 | 90,
    summary: {
      linesAdded: number,
      linesDeleted: number,
      linesChanged: number,
      activeDays: number,
      sessions: number,
      averageLinesPerActiveDay: number
    },
    dailyActivity: Array<{ date: string, linesAdded: number, linesChanged: number }>,
    comparison: {
      linesAddedPercent: number | null,
      activeDaysPercent: number | null,
      averageLinesPercent: number | null
    }
  }
}
{ type: "checkStarted" }
{ type: "checkCompleted", payload: AiEvaluation }
{ type: "checkFailed", payload: { message: string, retryable: boolean } }
```

## 8. Контракт AI-бекенду

Точний URL і спосіб авторизації визначаються конфігурацією середовища. Фронтенд використовує клієнтський адаптер, щоб не залежати від конкретного провайдера AI.

### Запит

```json
{
  "language": "TypeScript",
  "periodDays": 30,
  "current": {
    "linesAdded": 1200,
    "linesDeleted": 340,
    "activeDays": 18,
    "sessions": 26,
    "averageLinesPerActiveDay": 66.7
  },
  "previous": {
    "linesAdded": 940,
    "linesDeleted": 280,
    "activeDays": 14,
    "sessions": 20,
    "averageLinesPerActiveDay": 67.1
  }
}
```

### Відповідь

```json
{
  "score": 78,
  "trend": "improving",
  "summary": "Активність і обсяг роботи зросли порівняно з попереднім періодом.",
  "strengths": ["стабільна регулярність", "зростання обсягу практики"],
  "recommendations": [
    "Підтримувати регулярні короткі сесії",
    "Додати більше роботи над тестами та рефакторингом"
  ],
  "confidence": "medium"
}
```

AI-бекенд не повинен отримувати сирий код у межах цього продуктового сценарію. У разі відсутності даних бекенд повертає зрозумілий результат із `confidence: "low"`, а не вигадує оцінку.

## 9. Стани інтерфейсу

- **Порожній стан:** статистики ще немає; показати вибір мови, періоду та підказку почати роботу.
- **Готовий стан:** статистика відображається, кнопка активна.
- **Завантаження:** кнопка заблокована, показується індикатор перевірки.
- **Успіх:** оцінка та рекомендації показані разом із часом перевірки.
- **Помилка мережі:** зберегти локальну статистику, показати причину та кнопку повтору.
- **Недостатньо даних:** показати метрики, але позначити AI-оцінку як ненадійну або недоступну.
- **Налаштування не задані:** запропонувати вказати адресу AI-бекенду.

## 10. Приватність і безпека

- не надсилати сирий код без окремої майбутньої згоди користувача;
- не зберігати API-ключі у webview або репозиторії;
- використовувати `SecretStorage` для секретів;
- додати налаштування дозволу на надсилання агрегованої статистики;
- очищати та перевіряти всі дані перед передаванням у бекенд;
- не логувати токени, повні запити або персональні дані;
- чітко показувати, коли дані надсилаються зовнішньому сервісу.

## 11. Налаштування VS Code

Рекомендовані налаштування:

- `linkai.backendUrl` — URL AI-бекенду;
- `linkai.defaultLanguage` — мова за замовчуванням;
- `linkai.defaultPeriod` — період за замовчуванням;
- `linkai.includeComments` — враховувати рядки коментарів;
- `linkai.sendAggregatedStatistics` — дозвіл надсилати агреговані дані;
- `linkai.excludedPaths` — додаткові шаблони виключених шляхів.

## 12. Критерії приймання MVP

- команда відкриває екран LinkAI у VS Code;
- екран коректно працює у світлій і темній темах VS Code;
- користувач може змінити мову та період без перезавантаження вікна;
- статистика відображається для порожньої, малої та великої кількості даних;
- поточний і попередній періоди порівнюються однаковими правилами;
- натискання **«Перевірити»** показує стан завантаження та надсилає тільки агреговані дані;
- успішна відповідь AI відображає оцінку, пояснення, сильні сторони та рекомендації;
- помилка бекенду не стирає вже зібрану локальну статистику;
- відсутність мережі має зрозуміле повідомлення та можливість повторити запит;
- API-ключ не потрапляє до DOM, логів або вихідного коду webview;
- основні сценарії покриті тестами для підрахунку метрик, порівняння періодів і обробки повідомлень.

## 13. Етапи реалізації

1. Зареєструвати команду та створити webview-екран.
2. Додати типи повідомлень і базову оболонку UI.
3. Реалізувати збір та агрегацію локальної статистики.
4. Додати фільтри, ключові показники та графік.
5. Реалізувати клієнт AI-бекенду з типізованим контрактом.
6. Додати стани, помилки, налаштування та приватність.
7. Покрити критичні сценарії тестами й перевірити роботу в темній/світлій темах.
